# TubeFinder для Google Таблиц

Тот же поиск роликов, что и в приложении из папки `tubefinder/`, только внутри
таблицы: справа боковая панель с фильтрами и большой кнопкой «Поиск», результаты
ложатся в ячейки активного листа.

**Cloud Console, OAuth-клиент и API-ключ не нужны.** Скрипт ходит в YouTube через
встроенную службу Apps Script, а разрешение выдаёт тот аккаунт, под которым открыта
таблица.

## Установка (5 минут)

1. Откройте нужную Google Таблицу → **Расширения → Apps Script**.
2. В файл `Код.gs` (`Code.gs`) вставьте содержимое [`Code.gs`](Code.gs), заменив всё,
   что там было.
3. Слева **Файлы → + → HTML**, назовите файл ровно `Sidebar` (без расширения)
   и вставьте в него содержимое [`Sidebar.html`](Sidebar.html).
4. Слева **Службы → +** → в списке найдите **YouTube Data API v3** → идентификатор
   оставьте `YouTube` → **Добавить**.
5. Сохраните проект (💾) и вернитесь в таблицу, обновите страницу.
6. В меню появится **TubeFinder → Поиск роликов…**. При первом запуске Google
   спросит разрешение — это обычное окно доступа к вашей же таблице и YouTube.

## Как пользоваться

В боковой панели: запрос (несколько — каждый с новой строки), большая кнопка
«Поиск», ниже — куда писать и фильтры.

**Куда писать:** дописать в текущий лист (шапка не дублируется), очистить текущий
лист, создать новый лист с именем по запросу и времени.

**Фильтры YouTube:** сортировка, период публикации (включая свой диапазон дат),
длительность, HD/SD, регион, язык, субтитры, Creative Commons, безопасный поиск,
трансляции, поиск внутри одного канала (`UC…`, `@handle` или ссылка).

**Точные условия** (считаются скриптом по данным `videos.list`): просмотры от/до,
длина в минутах от/до, обязательные слова в названии, стоп-слова (по названию и
описанию), фильтр по названию канала, исключить Shorts или оставить только их,
галочка «совпадение именно в названии» — при нескольких запросах ролик проходит,
если совпал хотя бы с одним.

**Порядок в таблице:** как выдал YouTube, по просмотрам, лайкам, дате, длительности
или вовлечённости (лайки / просмотры).

Пункт меню **«Повторить последний поиск»** прогоняет те же настройки ещё раз —
удобно обновлять подборку, не открывая панель.

## Колонки

`Название · Канал · Дата · Просмотры · Лайки · Комментарии · Длительность · Секунды ·
Тип · Запрос · Ссылка · ID видео · Описание`

«Секунды» продублированы числом, чтобы по ним работали формулы и сортировка листа;
«Тип» — `Shorts` или `видео`; «Запрос» показывает, какая строка поиска нашла ролик;
описание обрезается до 500 знаков.

## Квоты и ограничения

- Один `search.list` (страница до 50 роликов) стоит 100 единиц из суточных 10 000,
  уточнение деталей `videos.list` — 1 единицу. «Сколько найти = 200» это ~404 единицы.
  Несколько запросов в одном поиске тратят квоту пропорционально.
- Выполнение скрипта в Apps Script ограничено 6 минутами. Реально это ~200–300
  роликов за прогон; если ловите таймаут, уменьшите «Сколько найти» или разбейте
  запросы на несколько заходов.
- Точного «поиска только по заголовку» в YouTube API нет — галочка «совпадение
  именно в названии» досчитывается скриптом уже после выдачи.

## Проверено

Логика `Code.gs` прогнана в Node на подставных `YouTube` и `SpreadsheetApp`
(30 проверок): разбор ISO-длительности, сборка аргументов `search.list`, резолв
канала по `@handle` и по ссылке, два запроса в одном прогоне с дедупликацией,
фильтры (Shorts, стоп-слова, просмотры, обязательные слова), сортировка,
запись шапки и строк, дозапись в конец без дублирования шапки, сохранение
настроек и отказ на пустом запросе. Само выполнение внутри Google Таблиц
проверьте у себя — среды Apps Script здесь нет.
