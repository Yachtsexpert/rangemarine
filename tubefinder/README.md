# TubeFinder — свой поиск роликов на YouTube

Отдельное веб-приложение (не на YouTube): слева — результаты, справа — панель настроек
и большая кнопка **Поиск**. Вход по своему Google-аккаунту, поиск идёт через официальный
YouTube Data API v3 от вашего имени.

## Что умеет

**Поиск по названию.** Запрос уходит в YouTube, плюс опция «Искать совпадение именно
в названии» — она отсекает ролики, где ваши слова встретились только в описании.

**Фильтры YouTube** (применяются на стороне API): сортировка, период публикации
(24 часа / неделя / месяц / 3 месяца / год / свой диапазон дат), длительность, качество
(HD/SD), регион, язык, субтитры, лицензия Creative Commons, встраиваемость, безопасный
поиск, трансляции (идут / запланированы / завершены), поиск внутри одного канала
(по `UC…`, `@handle` или ссылке).

**Точные условия** (досчитываются в браузере по данным `videos.list`): просмотры от/до,
длительность от/до в минутах, обязательные слова, стоп-слова, фильтр по названию канала,
исключить Shorts или оставить только Shorts.

**Мой аккаунт:** только каналы из моих подписок / скрыть каналы, на которые я подписан.

**Остальное:** пресеты фильтров, сортировка выдачи (просмотры, лайки, дата,
длительность, вовлечённость = лайки/просмотры), список или плитка, «Загрузить ещё»,
экспорт результатов в CSV, последние настройки восстанавливаются при следующем открытии.

## Запуск

Нужен http-сервер: Google OAuth и ES-модули не работают с `file://`.

```bash
cd tubefinder
python3 -m http.server 8123      # или: npx serve -l 8123
```

Откройте http://localhost:8123.

## Настройка доступа (5 минут)

1. [Google Cloud Console](https://console.cloud.google.com/) → создайте проект.
2. **APIs & Services → Library** → включите **YouTube Data API v3**.
3. **OAuth consent screen** → тип *External*, заполните название и e-mail поддержки,
   добавьте scope `.../auth/youtube.readonly`, а себя — в **Test users**
   (пока приложение не опубликовано, входить могут только тестовые пользователи).
4. **Credentials → Create credentials → OAuth client ID → Web application**.
   В **Authorized JavaScript origins** добавьте адрес, с которого открываете приложение:
   `http://localhost:8123` и/или ваш домен.
5. (Необязательно) там же **Create credentials → API key** — с ним можно искать
   без входа в аккаунт.
6. В приложении нажмите **⚙ Доступ**, вставьте Client ID (и API-ключ, если делали),
   сохраните и нажмите **Войти через Google**.

Client ID и API-ключ хранятся только в localStorage вашего браузера, токен доступа —
в sessionStorage; бэкенда у приложения нет, данные никуда, кроме Google, не уходят.
API-ключ стоит ограничить в консоли по HTTP-referrer.

## Квоты

У проекта в Google Cloud 10 000 единиц квоты в сутки. Один поиск `search.list` стоит
100 единиц (одна страница = до 50 роликов), уточнение деталей `videos.list` — 1 единицу.
То есть «Сколько найти = 200» это 4 страницы ≈ 404 единицы, примерно 24 таких поиска
в день. Квоту можно расширить заявкой в Google.

## Структура

```
tubefinder/
├── index.html          разметка: слева результаты, справа настройки
├── assets/styles.css   тема (светлая/тёмная по системной), адаптив
└── js/
    ├── app.js          связывание UI, цикл поиска и пагинация
    ├── auth.js         вход через Google (OAuth token flow, без бэкенда)
    ├── youtube.js      обёртка YouTube Data API v3
    ├── filters.js      клиентские фильтры, сортировка, форматирование
    ├── ui.js           карточки, статистика, экспорт CSV
    └── store.js        localStorage: ключи, пресеты, настройки вида
```

## Ограничения

- Поиск идёт по индексу YouTube: точного «поиска только по заголовку» в API нет,
  поэтому строгое совпадение по названию фильтруется уже в браузере.
- `search.list` не отдаёт просмотры и длительность — они догружаются `videos.list`
  пачками по 50 ролику, поэтому фильтры по просмотрам/длине точные.
- Пока приложение в статусе *Testing* в Google Cloud, входить могут только аккаунты
  из списка Test users.
